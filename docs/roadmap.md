# Roadmap

---

## v0.1 — Local Control Plane

**Status:** DONE

**Scope:** End-to-end governed skill execution on the local filesystem. No external dependencies. Both Claude Code and OpenAI Codex are supported via dedicated instruction files.

**Delivered:**
- 5 registered skills: `morning_brief`, `vault_cleanup`, `research_digest`, `continuation_brief`, `policy_simulator`
- Policy engine with ALLOW / REQUIRE\_APPROVAL / DENY decisions and path traversal prevention
- Append-only audit log (`runs.jsonl`, `approvals.jsonl`) with heuristic secret scanning
- Vault memory model: `raw/` → `wiki/` promotion, `projects/` for deliverables, `daily/` for session logs
- `CLAUDE.md` and `AGENTS.md` operating rules for each agent client
- 41 passing tests (policy, registry, path validation, policy\_simulator)

**Concrete deliverable:** `python control_plane/run_skill.py --skill policy_simulator --input vault/raw/sample_action_manifest.json` produces a Markdown policy report in `vault/projects/` and logs the run to `data/runs.jsonl`.

---

## v0.2 — Approval Workflow Execution

**Status:** PLANNED

**Scope:** Make REQUIRE\_APPROVAL actions actionable. Today they are logged and blocked; in v0.2 the agent can prompt for approval at the CLI and re-execute after a user grants it.

**Planned:**
- Interactive approval prompt in `run_skill.py`: when a skill's action triggers REQUIRE\_APPROVAL, pause and display the action, path, and reason to the user
- `--approve <run_id>` CLI flag to action a previously logged pending approval
- Update `approvals.jsonl` records with `outcome: "approved"` or `outcome: "denied"` and a timestamp
- Time-bounded approval tokens: approvals expire after a configurable window (default 15 minutes)

**Concrete deliverable:** `python control_plane/run_skill.py --skill <name>` prompts "Allow GIT\_COMMIT? [y/N]" at the terminal rather than silently logging and blocking.

## v0.3 — Dashboard Observability

**Status:** PLANNED

**Scope:** A local, static web dashboard that reads `data/runs.jsonl` and renders skill execution history, policy decision distributions, and the pending approval queue — without any backend server or cloud dependency.

**Planned:**
- Next.js static export (or plain HTML/JS if dependency-free is preferred)
- Recharts visualisations: skill run frequency, status breakdown (success / path\_violation / error), policy decision distribution from `approvals.jsonl`
- Approval queue panel: lists pending records from `approvals.jsonl` with action and reason
- Generated by a new `dashboard` skill that reads JSONL and writes a `vault/projects/dashboard.html`

**Concrete deliverable:** `python control_plane/run_skill.py --skill dashboard` opens a self-contained HTML file in the browser showing the last 30 days of run history.

---

## v0.4 — Optional MCP / API Integrations

**Status:** PLANNED

**Scope:** Allow external tools — MCP servers, REST APIs, webhooks — to be registered as governed skills. They execute under the same policy and audit contract as local skills, with no special-casing.

**Planned:**
- MCP server adapter: expose all registered skills as MCP tools; incoming MCP calls routed through `run_skill.py` and `policy.py`
- Optional REST API wrapper: thin HTTP server (FastAPI or stdlib `http.server`) that accepts `POST /run` with `{"skill": "...", "input": "..."}` and returns the run record
- Webhook approval notifications: POST to a configured URL when a REQUIRE\_APPROVAL action is logged
- All integrations are opt-in via configuration; the core control plane remains dependency-free

**Concrete deliverable:** A Claude Desktop MCP config pointing at this repo exposes all 5 skills as governed MCP tools with full policy enforcement and audit logging.
