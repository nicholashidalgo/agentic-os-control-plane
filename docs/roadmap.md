# Roadmap

---

## v0.1 - Local Control Plane

**Status:** DONE

**Scope:** End-to-end governed skill execution on the local filesystem with no external service dependency.

**Delivered:**
- 5 registered skills: `morning_brief`, `vault_cleanup`, `research_digest`, `continuation_brief`, `policy_simulator`
- Policy engine with ALLOW / REQUIRE\_APPROVAL / DENY decisions and path traversal prevention
- Append-only audit log (`runs.jsonl`, `approvals.jsonl`) with heuristic secret scanning
- Vault memory model: `raw/` → `wiki/` promotion, `projects/` for deliverables, `daily/` for session logs
- dedicated operator instruction files
- 41 passing tests (policy, registry, path validation, policy\_simulator)

**Concrete deliverable:** `agentic-os run policy_simulator --input vault/raw/sample_action_manifest.json` produces a Markdown policy report in `vault/projects/` and logs the run to `data/runs.jsonl`.

---

## v0.2 - Approval Workflow Execution

**Status:** IN PROGRESS

**Scope:** Make REQUIRE\_APPROVAL actions actionable. Skills that trigger a policy gate now generate a structured approval record with a full status lifecycle (pending → approved / denied / expired) instead of silently failing.

**Delivered:**
- Structured approval records in `data/approvals.jsonl` with `approval_id` (format: `APR-YYYYMMDD-xxxxxx`), `status`, `created_at`, `expires_at`, `resolved_at`, `resolved_by`
- `src/agentic_os/control_plane/approvals.py` - `list_approvals()`, `get_approval()`, `resolve_approval()`, `is_expired()`
- `approvals list [--status pending]` - inspect the approval queue
- `approvals approve <id>` - approve and optionally rerun the skill
- `approvals deny <id>` - deny a pending approval
- `approval_timeout_hours` and `rerun_after_approval` config keys
- 10 new tests in `tests/test_approvals.py`

**Remaining for this milestone:**
- Full agentic CLI wrapper (delegated to next pass)
- Approval prompt during interactive session execution

**Concrete deliverable:** `agentic-os approvals list --status pending` shows all open approvals. `approvals approve APR-...` resolves the record and reruns the skill.

## v0.3 - Dashboard Observability

**Status:** PLANNED

**Scope:** A local, static web dashboard that reads `data/runs.jsonl` and renders skill execution history, policy decision distributions, and the pending approval queue, without a backend server.

**Planned:**
- Next.js static export (or plain HTML/JS if dependency-free is preferred)
- Recharts visualisations: skill run frequency, status breakdown (success / path\_violation / error), policy decision distribution from `approvals.jsonl`
- Approval queue panel: lists pending records from `approvals.jsonl` with action and reason
- Generated by a new `dashboard` skill that reads JSONL and writes a `vault/projects/dashboard.html`

**Concrete deliverable:** `agentic-os run dashboard` opens a self-contained HTML file in the browser showing the last 30 days of run history.

---

## v0.4 - Optional MCP / API Integrations

**Status:** PLANNED

**Scope:** Allow external tools, MCP servers, REST APIs, and webhooks, to be registered as governed skills. They execute under the same policy and audit contract as local skills, with no special-casing.

**Planned:**
- MCP server adapter: expose all registered skills as MCP tools; incoming MCP calls routed through `run_skill.py` and `policy.py`
- Optional REST API wrapper: thin HTTP server (FastAPI or stdlib `http.server`) that accepts `POST /run` with `{"skill": "...", "input": "..."}` and returns the run record
- Webhook approval notifications: POST to a configured URL when a REQUIRE\_APPROVAL action is logged
- All integrations are opt-in via configuration; the core control plane remains dependency-free

**Concrete deliverable:** An MCP configuration can expose the registered skills as governed tools with the same policy and audit controls as local execution.
